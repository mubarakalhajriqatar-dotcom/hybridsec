Add a tool

Lower-case letters, digits, - and _, starting with a letter; upper case is lowered for you.
Known shells, interpreters and launchers, script files, attack tools and the built-in scanners are always refused; the allow-list in .env decides the rest.
Separate arguments with spaces; each piece goes to the program as one argument, with no quotes and no shell. Use {target} for the run's target and, for a per-URL tool, {url}.
How it runs
The run's time budget is shared by all its tools, so a call may be stopped sooner.

How custom tools run

  • They are added, listed and run only from the machine running HybridSec.
  • Only {target} and {url} are filled in, from the checked, authorized target. Fixed addresses, host names, @server forms, proxies, option files and network shares in the arguments are refused. Other options you type (for example one that follows redirects) are trusted and could still lead the tool to another host.
  • Arguments go to the program as a list, never through a shell.
  • Each call is stopped at its time limit, once it prints more than 50,000 characters on standard output or on standard error (5,000 characters of standard error are kept), and inside the run's deadline. A run keeps at most 200,000 characters of custom-tool output in all.
  • Output is kept as text and exported, not parsed into findings or scored, and simulation mode works without the program installed.
Do not put passwords or API keys in arguments: commands are stored with every run and appear in reports. Arguments that look like secrets are refused.

The hybrid workflow

HybridSec chains several open-source security tools into one pipeline and uses an AI planner to describe, justify and sequence the steps:

  1. Nmap scans the top N TCP ports of the target, by default with service and version detection; the chosen profile can drop the version probes, add Nmap's default scripts or use polite timing.
  2. Open ports that look like web services (HTTP/HTTPS, common web ports) are converted into URLs.
  3. WhatWeb fingerprints each URL to identify servers, frameworks, CMSs and libraries.
  4. Nikto (optional) checks each web server for known misconfigurations and outdated software.
  5. Custom tools (optional, registered on the Custom tools page from the machine running HybridSec) run last, once on the target or once per web URL; their output is kept as text, not parsed into findings or scored.
  6. Results are correlated into a single report with a 0-100 risk score, highlights and downloadable JSON, CSV, HTML and Markdown exports.

The AI Planner turns a plain-language objective into a structured workflow (steps, inputs, outputs, command templates, safety controls). Plans can be saved and executed directly from the dashboard.

Simulation mode produces realistic sample data without any network traffic so the workflow can be demonstrated safely.

Configuration (.env)

The backend reads its settings from a .env file in the project root:

HYBRIDSEC_AI_PROVIDER=auto        # auto | anthropic | openai | rules
ANTHROPIC_API_KEY=sk-ant-...      # used when provider is auto/anthropic
ANTHROPIC_MODEL=claude-opus-5-5
OPENAI_API_KEY=sk-...             # any OpenAI-compatible endpoint
OPENAI_MODEL=gpt-4o-mini
OPENAI_BASE_URL=https://api.openai.com/v1
HYBRIDSEC_AI_TIMEOUT=120          # seconds per connect, read or write of a planner request (not the whole request)
HYBRIDSEC_HOST=127.0.0.1          # address the launch scripts bind
HYBRIDSEC_PORT=8000
HYBRIDSEC_ALLOWED_TARGETS=        # comma-separated hosts/CIDRs/*.domain; empty = any authorized target
HYBRIDSEC_ALLOWED_HOSTS=          # extra Host header names; localhost, 127.0.0.1 and ::1 are always accepted
HYBRIDSEC_CUSTOM_PROGRAMS=        # programs the Custom tools page accepts; empty = curl, dig, host, nslookup, whois, sslscan, sslyze, traceroute, tracert
HYBRIDSEC_ALLOW_SIMULATION=true   # allow simulated runs
HYBRIDSEC_MAX_TIMEOUT=900
HYBRIDSEC_DEFAULT_TIMEOUT=180
HYBRIDSEC_MAX_TOP_PORTS=1000
HYBRIDSEC_MAX_CONCURRENT_RUNS=3   # runs that may execute at the same time
HYBRIDSEC_DATA_DIR=./data

Without Anthropic or OpenAI credentials the planner falls back to the built-in rules provider, which produces a deterministic plan.

The planner, scanning-limit and simulation values can also be changed from the Settings page, which writes them to .env for you and applies them without a restart. HYBRIDSEC_AI_TIMEOUT, HYBRIDSEC_HOST, HYBRIDSEC_PORT, HYBRIDSEC_ALLOWED_HOSTS, HYBRIDSEC_CUSTOM_PROGRAMS and HYBRIDSEC_DATA_DIR are edited in .env only (the address, port and data folder take effect after a restart), and HYBRIDSEC_MAX_CONCURRENT_RUNS through PUT /api/settings.

Installing the tools

Ubuntu / Debian

sudo apt update
sudo apt install -y nmap whatweb nikto

WhatWeb may not be in older repositories; see the Kali column for a git install.

Kali Linux

sudo apt update
sudo apt install -y nmap whatweb nikto

# WhatWeb from source (any distro)
sudo apt install -y ruby ruby-dev git
git clone https://github.com/urbanadventurer/WhatWeb
cd WhatWeb && sudo make install

Windows

# Nmap (installer or winget)
winget install Insecure.Nmap

# WhatWeb / Nikto need Ruby / Perl.
# Easiest: run them in WSL (Ubuntu):
wsl --install -d Ubuntu
wsl sudo apt install -y nmap whatweb nikto

Alternatively use simulation mode on Windows hosts without the tools.
